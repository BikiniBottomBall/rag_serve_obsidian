# RAG-Grounded 反幻觉技能

此技能指导 agent 在进行任何知识性回答时，强制遵循 RAG（检索增强生成）工作流程，从根本上减少 AI 幻觉。

## 核心原则

**永远不要凭记忆回答知识性问题。** 所有涉及事实、概念、技术细节的回答，必须先检索知识库。

## 工作流程

### 第一步：判断是否需要检索

以下情况**必须**先检索 RAG 知识库（使用 `rag_query` 工具）：
- 用户询问某个概念、技术、工具的定义或用法
- 用户询问"我之前说过/写过什么"
- 用户要求推荐方案、最佳实践
- 任何你无法 100% 确定的事实性问题

以下情况可以跳过检索：
- 纯代码操作（读文件、写文件、执行命令）
- 用户明确要求用你自己的知识回答
- 闲聊性质的对话

### 第二步：执行检索

```
rag_query(query="用户问题的精确表述")
```

检索结果会包含：
- `answer`: RAG 引擎基于知识库生成的回答
- `sources`: 引用来源列表（文件名 + 相关度分数 + 文本片段）

### 第三步：基于检索结果回答

1. **有检索结果时**：
   - 以检索到的知识库内容为主要依据
   - 用自己的知识作为**补充**，而非主要来源
   - **必须**标注每条信息的来源文件
   - 格式：`> 📄 来源: 文件名.md`

2. **检索结果不足时**：
   - 明确说："我在知识库中没有找到相关内容"
   - 可以说："根据我的通用知识，[内容]，但请注意这未在您的知识库中验证"
   - 建议用户补充相关知识到 Obsidian 笔记

3. **检索结果与你的知识冲突时**：
   - **以用户知识库为准**
   - 说明差异："我的一般理解是 X，但您的知识库记录的是 Y，我以您的记录为准"

### 第四步：不确定性标注

对每个断言使用以下标注：

| 信心等级 | 标注 | 含义 |
|---------|------|------|
| ✅ 确定 | `[已验证]` | 来自知识库的直接检索结果 |
| ⚠️ 推测 | `[推测]` | 基于检索结果的合理推断 |
| ❓ 不确定 | `[不确定]` | 无法从知识库验证，来自通用知识 |
| 🔍 待查 | `[待验证]` | 需要进一步检索才能确认 |

## 对话记录反思

当用户询问关于代码构建过程的问题时：

1. 首先检索 `opencode对话记录/` 目录下的历史会话
2. 使用 `rag_query` 搜索相关对话主题
3. 从历史对话中提取经验教训
4. 总结：哪些模式有效、哪些模式导致了问题、下次如何改进

示例：
```
rag_query(query="session 中关于 agent-forge 项目的讨论和架构决策")
```

## 知识库维护

定期建议用户：
- 将重要的技术发现写入 Obsidian 笔记
- 对过时的笔记进行更新
- 使用 `rag_reindex` 在大量更新后重建索引

## 禁止事项

1. ❌ 在检索前就给出确定性的知识回答
2. ❌ 编造不存在的文件名或引用来源
3. ❌ 忽略检索结果中的内容，坚持自己的"记忆"
4. ❌ 对不确定的内容表现得确定
5. ❌ 使用模糊来源标注如"根据资料显示"——必须给出具体文件名
